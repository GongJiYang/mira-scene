# 挑战方向（每项都有退路）

> 来源：第 1 轮（第一性原理）中，被判定为「可以挑战的惯例」的假设。
> 用户原则：**要挑战，但必须有退路；效果不理想时可以补救。**
> 每一项都写明：挑战方案 / 退路 / 什么时候切换到退路 / 在哪一轮做决定。

---

## C1 · 挑战「一问一答的轮次制」（假设 A3）

| 项 | 内容 |
|---|---|
| 现有方案（退路） | 轮次制：一轮回复是一条可以整条作废的时间线（D3、D12），S1/S2 已经实现并测试过 |
| 挑战方案 | 全双工连续流：用户和角色可以同时发声，用语音活动检测判断用户什么时候真正开口，并区分「嗯」「对」这类附和与真正的打断 |
| 价值 | 更接近真人对话；对应题目可选扩展「实时语音」，用户已确定会做这个方向 |
| 风险 | 回声消除；附和与打断的误判；指令和时间线在连续流里很难对齐 |
| 关键洞察 | 两者不一定互斥：**全双工可以做在输入侧，输出侧仍然用轮次时间线**。语音活动检测判定一次「真打断」，就等同于触发一次 PTT_DOWN，reducer 不需要改 |
| 切换到退路的条件 | 预研时误打断率明显偏高，或者手机外放的回声无法消除 → 退回按住说话（D2），自动检测作为可选开关 |
| 决定的轮次 | 第 5 轮 `event-driven-api-design` |

## C2 · 挑战「指令由 LLM 直接输出」（假设 A6）→ 导演层

| 项 | 内容 |
|---|---|
| 现有方案（退路） | LLM 每个 beat 直接输出 emotion / pose / action / camera / fx / media（D5），由 `parseBeatLenient` 做降级 |
| 挑战方案 | **导演层**：LLM 只负责台词，外加从**封闭标签表**中挑选情绪和意图；由导演层把这些标签映射成画面（表情、姿势、镜头、特效、媒体）和声音（Fish 的括号指令）。剧情节点触发的视觉事件完全由导演层的规则决定 |
| 已验证的先例 | 用户的项目 voice-workbench（读声 Readcue）中的 `backend/app/speech/emotion_vocab.py`：遵循 Fish S2 指南的封闭情绪标签表；`prompt_table()` 交给 DeepSeek；`render()` 输出 `[sad][whispering]`；`normalize()` 把不合法的值兜底回表内。**已在线上使用过** |
| 价值 | LLM 输出格式的压力大幅下降（直接降低 P1 最难部分的风险）；画面稳定可控；Mock 模式可以直接复用导演层；情绪同时作用于画面和声音 |
| 风险 | 表演的灵活性下降（只能使用表里已有的组合） |
| 补救方式 | 导演层允许 LLM 可选地给出「建议动作」，导演层判断合法就采纳，不合法就按规则处理，等于两种方案的混合 |
| 切换到退路的条件 | 规则映射出来的表演明显呆板 → 放开更多字段让 LLM 直接决定（回到 D5） |
| 决定的轮次 | 第 6 轮 `design-by-contract` |
