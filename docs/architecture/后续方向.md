## 二、动作管线：AI 视频 → Live2D（✅ 首尾闭环已批准，🔍 参数拟合待验证）

D50 的发现：**用 Live2D 截图作图生视频的首帧，切入就能无缝**（掩码 IoU 0.966）。在此基础上：

### 2.1 首尾闭环片段 ✅
提示词要求「最后回到起始姿势」，首帧、末帧都与 Live2D 配准 → 切入、切出都无缝，不再需要信号抖动遮盖。自动质检：首帧与末帧对 Live2D 的掩码 IoU ≥ 0.9，不达标自动重生成。

### 2.2 渲染比对拟合：把视频动作「复制」成 Live2D 参数 🔍
- **能复制的范围由皮套决定**：忧奈 185 个参数里可主动驱动的约 15 个（头 XYZ、身体 XYZ、眼开闭 / 眯眼 / 眼球、眉、嘴开合 / 嘴型）；腿（固定蹲姿）、手臂（物理输出，抬不起）、转身（无背面）复制不了。
- **方法**：不用人体姿态识别（真人模型对动漫脸不稳），反过来**逐帧在约 15 维参数空间搜索，使渲染出的 Live2D 与绿幕抠出的视频帧最像**（轮廓重合 + 边缘 / 五官位置），上一帧热启动、时间平滑，输出 Cubism 标准 `motion3.json`。
- **自带分流**：拟合误差小 → 转 motion3（原生分辨率、60fps、可打断、可叠加口型）；误差大（超出皮套能力，如站起来）→ 保留为视频片段（AI 超分）+ 首尾配准切换。

```
Live2D 截图作首帧 → Grok（限定：保持蹲姿、只动头与上半身、回到起始姿势）
  → 抠像 → 参数拟合
      ├ 误差小 → motion3.json → Live2D 动作库
      └ 误差大 → 视频片段（超分）+ 首尾配准切换
```

- **可行性验证**：用户生成一段「蹲姿 + 歪头、点头、东张西望、闭眼笑、回到起始姿势」的测试片段；Claude 写拟合原型，并排对比「原视频 / Live2D 复现」与逐帧误差。判据：平均轮廓 IoU ≥ 0.9 且观感成立。
- **全身动作**需要能站立、手臂与腿都有变形器的皮套（自动化管线的长期目标），或改用 Spine / VRM 这类骨骼方案。

## 三、平台方向 💬

- **社区 / UGC**：用户用管线把立绘自制成 Live2D 并上传。现有角色包（`pack.json` + `content.json`）已数据驱动，是起点；前提是管线全自动 + 客观验收指标，否则上传质量无法保证——这也说明验收指标是长期最值得投入的部分。项目仍是雏形，暂不展开。
- **本场高光自动成片**：从观测日志挑高光（第一次笑、reveal、跳舞、告别），套用宣传片的 Remotion 模板剪 15s。需评估 token 与渲染成本，后议。

## 四、界面与玩法 📌（已采纳，排在后续）

- 下播回顾卡：时长、聊过的关键词、开播截图、最后一句话，可保存分享。
- 礼物触发跳舞：连续送 3 次礼物，她跳一段（复用 D50）。
- 真实时间的直播间：按访问者本地时间切换深夜 / 通宵后清晨等场景，顶栏时长取真实时间。
- 多结局：按好感度与对话走向切不同告别片段（关推流 / 被劝着再播一首 / 趴着睡着），每段用首尾闭环片段实现。
