## §1 行为（契约）
- 触发条件：剧情截图（story media，`type: "photo"`）已调度但**尚未就绪**（客户端 C 状态机处于加载中，截图卡片显示 loading），且对话状态机 A 为 idle、连接正常。
- 动作：A 回到 idle 后约 **1.5s** 发起一次插话（复用现有 `nudge` 消息与服务端 nudge 轮）；之后截图仍未就绪，每隔约 **10s** 再插一次；**每个截图事件最多 3 次**。
- 截图就绪（`media_ready` ready）或失败（failed，走现有预置图兜底）→ 立即停止后续铺垫计划；已在说的那句照常说完。
- 用户开口 / 发弹幕 / 点击打断 → 照现有打断机制处理，并取消剩余铺垫计划。
- 这 3 次铺垫**不受**现有 nudge 频率限制（`state/nudge.ts`）约束，但也**不计入**它的计数；普通 nudge 规则不变。
- 铺垫轮不计入剧情推进的真实用户轮（现有 nudge 已不计入，保持）。

## §2 服务端：铺垫轮的提示词
- nudge 轮开始时，若本会话存在「已调度、未就绪」的剧情照片事件，`scene_notes` 追加一句提示（写进角色包 `characters/yuna/content.json` 新字段 `photoWaitingNote`，代码只读字段，不在代码里写死文案），语义：你正在翻找那张第一次开播的截图，还没找到，边找边和观众说一两句和刚才话题相关的话；不要说已经找到、不要描述截图内容；一两句即可。
- 文案由 Claude 定稿，就用下面这句（照抄进 `photoWaitingNote`）：
  `你正在电脑里翻那张第一次开播的截图，还没翻到。边找边跟观众随口说一两句，接着刚才的话题；不要说已经找到，也不要描述截图里有什么。`
- 「是否有未就绪照片」用纯函数判定（输入：会话已调度的剧情媒体事件与已就绪 / 失败集合），单测覆盖。
