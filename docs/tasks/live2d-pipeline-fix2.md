# Live2D 流水线 修复轮 2（只修嘴部 + 一个色点）

背景：`docs/tasks/live2d-pipeline-fix1.md`、`~/tools/pipeline-out/run3/report.md`。铁律不变。产物输出到 `~/tools/pipeline-out/run4/`，run3 保留。
架构师目测：run3 的闭眼、空洞、头发竖条都已经合格，**这一轮不要动它们**（这几项的指标只允许持平或更好）。嘴部在数字上判了「达标」，但**目测不合格**，下面三个问题都要修。

## 1. 全张嘴（p4）：下唇挂着两团粉色「水滴」
- 原因推测：口型贴片的掩码边缘不规则，并且有锯齿（`check_cmp4_mouth.png` 里的 run3 p4）。
- 修法：口型变体图层（closed / small / open）**统一使用同一个平滑掩码**。以嘴部为中心，取三张口型图变化区域的并集，再求外接椭圆，向外扩 6–10px，高斯羽化（σ≈3），超出这个掩码的像素一律透明。掩码内部的皮肤用 master 对应位置的像素补齐，这样三张图在边界上颜色完全一致。
- 指标：嘴部掩码边缘的锯齿度（相邻像素 |Δα| 的分布）；嘴部区域内的连通块数量（要求每个变体只有 1 块）；p4 与 `mouth_open` 素材的平均色差（不得劣于 run3 的 3.2）。

## 2. 半张嘴（0.5）：两张嘴叠在一起
- 原因：closed 与 open 之间按透明度做了交叉淡化。
- 修法：改为**三档互斥切换，不做交叉淡化**。`ParamMouthOpenY` 在 [0, 0.33) 显示 closed，[0.33, 0.66) 显示 `mouth_small`，[0.66, 1] 显示 open。用 psd2live 的互斥变体机制实现（参照 PSD_LAYER_SPEC 中「Numbers and variants」一节：共享参数、不同的关联 ID，也就是 exclusive variants；必要时改用 layout manifest 的 `variant` 字段）。不得修改 psd2live 源码；如果它只支持开关式变体，就在报告里写明，并给出最接近的替代方案。
- 指标：在 `ParamMouthOpenY` = 0 / 0.2 / 0.5 / 0.8 / 1 五个姿态下，嘴部区域与对应素材的平均色差；任意一个姿态里，同时可见的口型层数必须 = 1。

## 3. 闭嘴（rest）：下方有一道浅色残影
- 原因推测：See-through 原来的 mouth 层（或原图的嘴部轮廓）没有被完全盖住。
- 修法：以 master 的嘴部作为 closed 变体，并用第 1 点的统一掩码完全覆盖 face 层上的旧嘴；face 层在这个掩码范围内的嘴部线条，用周围的皮肤补画抹掉。
- 指标：rest 姿态下，嘴部掩码外 10px 环带与 master 的平均色差。

## 4. 风衣右侧边缘的蓝色色点
- 现象：拍平图中，风衣右边缘约 (975, 1040)（原图坐标）有一个小蓝点，run2 和 run3 都有。先定位它来自哪一层，再修掉。
- 指标：该区域的最大色差。

## 完成标准
- `run.sh` 生成 run4；验收导出在原有基础上增加 `ParamMouthOpenY` = 0.2 / 0.8 两个姿态，以及 mp4、web。
- `run4/compare/`：嘴部 5 档的对比图（run3 和 run4 并排，并附上对应素材）、蓝点区域对比图，另外附一张 run3→run4 的回归检查图（闭眼、脖子、头发三处并排）。
- 在 `run4/report.md` 里列出各项指标的变化（run3 → run4）以及回归项的指标；不要宣称效果自然。

## 追加：用户在 run3 网页播放器中目测发现的问题（优先级高于以上各项）

用户用鼠标拖动视线和头部做了测试。下面每一条都要先**诊断**（用数据证明根因），再修复，并附上 run3 与 run4 的对比检查图。

### 5. 眼睛：眼球轮廓隐约可见；往下看时眼球整个露出，周围有一圈黑色横线
- 根因推测：虹膜只裁剪到合成出来的眼白椭圆上，而这个椭圆比眼皮的开口大；原图的下眼线和睫毛残留在 face 层上。
- 修法：
  - **眼白形状改为原图中真实的眼皮开口**：从原图提取上睫毛下沿与下眼睑线之间围成的区域，形状要实心，不能是环形。
  - 虹膜和眼白都裁剪到这个开口区域内。
  - face 层在眼部开口及其外圈 3px 范围内的眼线、睫毛残留，用周围皮肤颜色补画掉。
- 验收导出：`ParamEyeBallY=-1`（往下）、`ParamEyeBallY=1`（往上）、`ParamEyeBallX=±1`，以及四个对角方向。
- 指标：每个视线姿态下，「虹膜像素落在眼皮开口之外」的数量必须为 0；眼部外圈 3px 环带内的暗线像素数（亮度 <80），run3 和 run4 对比。

### 6. 脖子完全透明；头往左下、右下转时头和脖子脱开
- 先诊断：输出 neck 层的 alpha 覆盖率，以及它在 face 下方的延伸长度。
- 修法：重建一个**实心**的 neck 层。肤色取原图脖子可见部分的中位数，形状从高领上沿一直向上延伸到下巴以上 40–60px（藏在 face 下面）；宽度取原图脖子的宽度。
- 验收导出：`ParamAngleX=±30` 与 `ParamAngleY=-30` 的组合，以及 `ParamAngleZ=±20`。
- 指标：这些姿态下，下巴与领口之间的空洞像素数必须为 0。

### 7. 两个耳坠、两张嘴（头部转动后重影）
- 先诊断：检查 face、hair、ears 各层里是否还残留耳坠或嘴的像素（与 earwear、mouth 独立层的位置重叠，且颜色相近），把残留像素数列出来。
- 修法：从 face、hair、ears 层中**抹掉**残留的耳坠和嘴，用周围的皮肤或头发补画，只保留独立图层里的那一份。
- 指标：残留像素数 → 0；头部转动姿态下，耳坠区域连通块数必须为 1。

### 8. 头往左上、右上转时脸部效果不理想
- 查清楚 psd2live 的头部变形强度有哪些可配置项（CLI 参数、预设 minimal/default/full、项目设置），**不改源码**。分别用至少两种设置导出 `ParamAngleX=±30, ParamAngleY=30` 的对比图。如果没有可调的配置项，就在报告里写明，并给出可行的后续方案（例如 MCP 精修）。

### 回归要求
run3 已经合格的闭眼、头发竖条、内部空洞，在 run4 中指标只能持平或变好。
