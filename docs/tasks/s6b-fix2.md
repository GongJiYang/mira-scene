# S6b-fix2：fix1 验收后剩下的 3 个问题

> s6b.md 铁律有效。不要打开图片；长命令显式传大 timeout，同一命令超时两次就停下报告。

## 1. 客户端「等待新会话」期间丢掉了 error 和 pong
- `shouldAcceptMessage` 在 `awaitingSession` 时只接受 `session`，其它全丢：切频道失败（服务端回 `unknown_character`）时客户端收不到错误、卡在等待；心跳 `pong` 被丢可能误判断线。
- 改法：等待期间 `pong` 一律接受；`error` 接受并结束等待（进入错误态，`retryable` 按消息）；其它带旧 sessionId 的消息仍丢弃。补单测。

## 2. 手机端夏凛：桌子下面露出下半身
- fix1 把图层底部抬到 120px 后，角色基底在桌沿以下的部分（手、风衣下摆）仍然可见，看起来像桌子悬在她身上（`e2e/out/live-rin-mobile.png`）。
- 改法：手机竖屏时，角色基底层按**前景桌图层的不透明下沿**裁切（`clip-path` 或容器 `overflow:hidden` + 高度），桌沿以下只显示背景；裁切位置由纯函数根据两个图层矩形计算并单测。桌面布局不受影响。
- 验证：用脚本在截图里测量——桌沿下方 40px 内，角色基底层的不透明像素数为 0（在 e2e 里断言，读图层的 bounding rect 与裁切值即可，不需要看图）。

## 3. 夏凛前景桌素材里烧进了「假透明」棋盘格
- `fg_table` 系列 PNG（以及桌面横版对应素材）右侧咖啡杯杯柄附近有一块灰白棋盘格，是生成素材时的假透明背景被画进了像素里。
- 改法：写一个可重复运行的修图脚本（`tools/asset-fix/checker.py` 或 ts）：在**指定区域**内识别两种交替灰白色（约 #FFFFFF / #CCCCCC 一类、8–16px 方格）的像素，把它们改为完全透明；区域外像素逐字节不变（断言）。原图先备份到 `assets/raw/_backup/`（不提交备份目录，加进 .gitignore），输出覆盖原文件。脚本打印改动像素数。
- 不确定区域时，先用脚本统计棋盘格特征像素的分布并打印坐标范围，再处理；报告里写清处理了哪些文件、各改了多少像素。
