## 架构关卡结论（mira-code-gate 关卡 1–5，用户已批准，优先级最高）
1. **YAGNI**
   - **本批要做**：背景三态（雨夜 / 雨停 / 打烊）切换时淡入淡出；代码绘制的雨；推镜头；前景桌面；拍立得显影（使用预置照片）；角色占位（D24 分层立绘，由状态机 B 驱动）；主动开口接入服务端。
   - **本批不做**：Live2D 运行时、实时生图、视差景深、剧情视频片段、正式 UI 样式（UI 由用户另行设计，本批只保证结构和占位）。
2. **端口 / 适配器**
   - 客户端定义 `StageRenderer` 接口，输入为视图模型快照（phase、visual、表演帧、media、C 状态），本批实现 **DOM + CSS + 一个雨用 canvas**。以后换成 Live2D 只需新增一种实现，核心不变。
   - 服务端定义 `MediaPort`，本批只实现「预置照片」这一个适配器。
3. **函数式核心 / 命令式外壳**：以下 4 个必须是纯函数，并且写单测：
   - `composeStage(vm) → Layer[]`：每层包含 `{id, src, opacity, transform, z}`；
   - `rainParams(fx, tMs) → {count, speed, alpha}`；
   - `cameraTransform(camera, progress) → {scale, tx, ty}`；
   - `developProgress(elapsedMs) → 0..1`。
   DOM、canvas、计时器都放在外壳层。
4. **契约式设计**
   - 任何素材加载失败都**不能卡住状态机**：背景加载失败时用纯色兜底（深蓝 #1b2233）；照片加载失败时换另一张预置照片，C 状态机转到 fallback（Q8）；角色贴片加载失败时只显示 master。
   - 渲染层只读视图模型，**不得 dispatch 任何 action**，唯一例外是 C 状态机的图片加载结果回调，它必须经过 controller。
5. **测试奖杯**
   - 纯函数写单测；集成测试验证「视图模型变化 → Layer[] 变化」。
   - 引入 **Playwright** 做少量端到端测试（详见 §8），并保存截图。**不做像素级比对。**
6. **技术选型**：舞台用 DOM + CSS，雨用 1 个 canvas。不引入 PixiJS。

## 2. 舞台布局（移动端优先，Q9）
- 舞台按 2:3 保持比例：手机上宽度占满，桌面上居中显示，**任何尺寸都不能出现横向滚动**。
- 层级从下到上：背景 → 雨 canvas → 角色 → 前景桌面 → 拍立得 → 字幕与输入占位 UI。
- 角色按 `composition.json` 的 `characterClipBottom` 裁剪，前景桌面必须盖住裁剪线以下的部分。

## 3. 背景与特效
| beat 字段 | 效果 |
|---|---|
| `fx: rain_heavy` | 雨的强度 1.0（会话开始时） |
| `fx: rain_stop` | 雨在 4s 内渐停；背景 1.2s 淡入切换到 rainstop |
| `fx: lights_dim` | 背景切换到 closing |
| `fx: warm_glow` | 叠一层暖色光（radial-gradient，透明度 0.25） |
- 特效属于持续状态：取 visual.fx 的最新值，保持到下一次变化为止。
- 雨：canvas 斜线雨滴，数量和速度由 `rainParams` 决定；用户开启「减少动态效果」（`prefers-reduced-motion`）时雨量减半。

## 4. 镜头
- `camera: close_up` 时，整个舞台容器（背景、角色、前景一起）在 800ms 内放大到 1.18 倍，中心对准角色脸部（约在画面 (0.5, 0.28) 处）；`wide` 时恢复到 1.0。使用 CSS transform 实现，由 `cameraTransform` 计算。

## 5. 角色占位（D24 分层立绘，由状态机 B 驱动）
- 底图用 master，贴片按 `render/manifest.ts` 和 B 的表演帧叠加：表情（face）、眨眼（open/half/closed）、口型（closed/small/open）、手势（hands：cup/polaroid/camera/phone，200ms 交叉淡化，对应 `handsTransition`）。
- 呼吸：角色容器做 ±0.6% 的竖向缩放，周期 4s（CSS 动画，打开 `prefers-reduced-motion` 时关闭）。
- 倾听时前倾：listening 状态下角色整体放大 1.02 倍，并上移 4px。

## 6. 拍立得显影（D27，状态机 C）
- 服务端：beat 的 media 中新增可选字段 `storyEventId`（只能在 protocol 中**新增**，由导演层生成，格式为 `<sessionId>:<turn>:<seq>`）。导演层产出带 `media:{type:"photo"}` 的 beat 时，`MediaPort.preset` 在 **2.5s 后**（可配置）发送 `media_ready{storyEventId, media:{type:"photo", id, url:"/stage/photos/<id>.png"}, status:"ready"}`。**这条消息属于剧情层事件：打断时不中止，也不按 turnId 过滤**（D27）。
- 客户端：带 media 的 beat **开始播放时**，向 C 发送 `REQUEST(storyEventId)`，进入 developing，桌面上出现一张空白相纸（白色卡片，从桌沿滑入）。收到 `media_ready` 后进入 ready；在 A 不处于 speaking 或 listening 时，进入 shown 并开始显影（图像透明度按 `developProgress` 在 3s 内从 0 升到 1，同时带一点褪色到正常的滤镜过渡）。图片加载失败时转为 fallback，改用另一张预置照片继续显影。
- 显影完成后，照片放大浮在舞台中央，点击或 6s 后回到桌面角落。

## 7. 主动开口接入服务端（D32，S3 挪过来的项）
- protocol 新增客户端消息 `nudge{turnId}`。客户端在 B 产出 nudge、A 为 idle 且连接正常时发送；turnId 递增，按一次新输入处理。频率限制：每 30s 最多 1 次；用户没有说话时最多连续触发 3 次，用户一开口就重置计数。
- 服务端：按 s3.md §7 的原方案处理。user_text 固定为「（客人安静地坐着，没有说话）」，动态后缀追加一句提示；这一轮不计入 trust，也**不计入会话限额**。Mock 模式下返回一句主动台词（例如低头抿咖啡、看一眼窗外，再轻声说一句）。
