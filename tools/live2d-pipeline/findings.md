### 1. 与任务说明冲突、必须报告的四处

**(a) 第 1 条"下巴和高领之间的透明缝"在 run2 的产物里不存在透明像素。** 实测（`compare/metrics.json` → `1_holes`）：
run2 全图空洞 **1877px**，其中**内部空洞 901px**、轮廓边 976px；下巴—领口带（zone [294,546]–[720,696]）内
`hole_pixels = 0`、`transparent_band_pixels = 8`（8 个像素，是阈值 0.95 的边缘像素）。
那条带子上真正的问题是**颜色**：原图是皮肤（y 570–610 处 RGB ≈ (171,132,116)），模型画的是 topwear
的领口阴影（≈ (125,109,103)），平均色差 **12.0**，最大 153（`max` 来自下巴边缘的发丝/描边）。
所以本轮按"色带 + 真实空洞"两个方向修：

- 真实内部空洞 826px（按 `compare` 口径 901px，差在轮廓边像素是否算作内部）→ **0**：最大一块 809px 在
  (503,1480)–(537,1522)（裙摆下方被丢掉的像素），另有 (338,616) 的 9px 和几个 1–5px 的缝。
  run3 全图只剩 842px，全部在轮廓边（back hair 800、topwear 16、handwear 26），内部为 0。
- 下巴—领口带色差 **12.0 → 3.05**（`compare` 口径），`step6` 的修复过程量到 6621px 的带子 37.81 → 2.26。

**(b) `assets/parts/eyelid_closed.png` 并不是"只有眼部非透明"。** 实测：alpha≥1 的像素 102246 个，
bbox (306,296,410,312)，连通成一片脸块；alpha 只有 0/255 两档（130 个中间值）。它的眼睛确实是闭的
（虹膜色相像素 0，M1 为 638/607），但和它同源的 `mouth_open.png`/`mouth_small.png` 也是整张脸块
（alpha 指纹完全相同，RGB 在眼、眉、嘴、下巴各处都与 M1 有 9–18 的平均差）。因此直接整块叠上去会
把变体自带的眼/眉/嘴一起贴进来。做法：**按语义 ROI 限制 + 只取与原图差异处**（`variant_layers`
里的 `roi_expand`、`diff_threshold`、`diff_ramp`），皮肤上与原图一致的像素一律不要。

**(c) `mouth_small` 无法成为第三个口型状态。** 证据链：`LayerClassifier.prefixMatch` 把
`mouth small` 归成 `MOUTH`（前缀 `mouth `），不是 `MOUTH_OPEN`；psd2live 的 preset 只有
`MOUTH_OPEN opacity = ramp(ParamMouthOpenY, 0…teethFade…1)` 和 `MOUTH_CLOSE = 1-…` 两态
（`RigBuilder.kt` 的 `LayerType.PRESET` 分支）；三态需要 switch 变体（编辑器/MCP 的
`layer_set_variant`），而 CLI 的 `--input` 只接受 PSD（`PSD2LivePipeline.run(psd: Path, …)`），
layout manifest 进不来。结论：`mouth open` 用 `mouth_open.png`，`mouth close` 用原嘴层；
`mouth_small` 只作为 `ParamMouthOpenY=0.5` 那一张检查图的**参照**（与它的平均色差：`compare` 口径 13.07，
第 8 步自己更大的 ROI 口径 11.6 —— 两个 ROI 不同，都在报告里）。
这条是偏离任务文本的地方，没有偷偷改验收标准——`p7` 姿态照任务要求导出了。

**(d) 第 6 条"只保留与睫毛主曲线相连的块"按字面实现会削掉内眼角睫毛。** run2 的 `eyelash-l`
第二块 149px（中心 (561,378)，在内眼角、不在主块上）；`eyelash-r` 的 335px、91px 才是漂在眼外的
褐色笔触。实现改成：**最大块永远保留**（它就是睫毛线），其余块必须落在贴着眼眶的带子里
（`band_rx_ratio 1.25 / band_ry_ratio 1.30`，块内 ≥50% 像素在带内）且形心不超过椭圆上沿 8px，
否则删。另外加了一道收尾：乘完软边权重后再按 α>0.25 去一次 1px 碎片（新配置 `lash_residual_speck_area: 4`，
原来这步是 `drop_specks(dark, 1)`，等于不删）。结果：`eyelash-r` 5 块→**2 块**（删掉 335/91px 的漂笔触和两个 1px
碎片，保留 840+480），`eyelash-l` 仍是 **2 块**（716→976 主块 + 28px 内眼角块）。

### 2. 第 7 条的指标说明（数字变了，但要看清是哪一部分）

run2 **不是**最近邻放大：第 4 步一直用 cubic。所以"阶梯"在 alpha 直方图上表现不出量化台阶
（`step_fraction` 两边都是 0，alpha 层级都是 244）。本轮按任务要求做的是：图层边界与原图轮廓重合处
**直接取原图 alpha**（`alpha_from_original`，同时取原图颜色，且只作用在 1–2px 的边界带内，
不碰内部补画色），其余处用 Lanczos + σ=0.9 的高斯。指标结果：

| 指标 | run2 | run3 |
|---|---|---|
| 前发软边相邻像素 \|Δα\| 均值 | 0.1327 | **0.1253** |
| 全图轮廓处 alpha 与原图平均误差 | 0.3653 | **0.2660** |
| 其中前发框内（609px 带） | 0.2509 | **0.1408** |
| 误差 >0.25 的轮廓像素占比 | 52.28% | **39.95%** |
| 后发软边 \|Δα\| 均值 | 0.1127 | **0.0618** |

σ 是在 0.0/0.3/0.4/0.6/0.9/1.2 里比出来的（步长 0.3 起前发均值才低于 run2）；1.2 数字更好但边缘
会更糊，取 0.9。

## 执行者判断（修复轮 2：run3 → run4）

> 全部结论来自像素统计，`compare/metrics.json` 里可以逐条复算。我**没有目测图像的能力**，
> 检查图只保证"同一段代码、同一区域、两个运行的行并列"，是否"自然"必须人工看。

### 1. 口型三态互斥：不是淡入淡出，而是三段硬切（我方主动偏离任务文本之处）

psd2live 的命令行只把 `ParamMouthOpenY` 映射成两条 opacity 斜坡（`MOUTH_CLOSE = 1-x`、
`MOUTH_OPEN = ramp(x/fadeIn)`，`fadeIn=0.15`），三层口型在 0.5 处必然同时可见——run3 的实测就是
`mouth close 1252px + mouth open 703px`，**可见层数 2**。本轮改成走 psd2live 自己的 headless MCP
（`psd2live mcp`，用其仓库里发布的 `mcp_proxy.py` 客户端，未改动 psd2live 一行代码），在
`ParamMouthOpenY` 的 0–1 密集网格（步长 0.02，边界 0.33/0.66 两侧各 ±0.004）上给三个口型层逐帧写
不透明度（每层 56 个关键帧），得到的是**阶跃**：

| 状态 | run3 与素材平均色差 / 可见层数 | run4 与素材平均色差 / 可见层数 |
|---|---|---|
| 0.0 | 3.93 / 1 | **0.05 / 1** |
| 0.2 | 未导出 | **0.05 / 1** |
| 0.5 | 52.41 / **2** | **20.24 / 1** |
| 0.8 | 未导出 | 17.44 / 1 |
| 1.0 | 4.82 / 1 | 3.16 / 1 |

代价：0.33/0.66 处是硬切换，网页播放器里看起来是"跳一下"，不是变形。这是"三态互斥"的直接后果。
0.5 档与 `mouth_small` 素材仍有 20.24 的平均色差，因为该素材是整张脸块，只在口型 ROI 内采样，
素材本身与原图的口型也不完全同位置。

### 2. 风衣右边缘蓝点：根因是第 4 步的"补画"颜色

蓝点区 (950,1015)–(1005,1115)：run3 有 **454px** "原图透明、模型不透明"的像素、**2 个**越界块
（最大 453px）；run4 是 **0px / 0 块**。区内平均色差 12.55 → 13.28（略升）、最大 139.33 → 128.0。
根因：第 4 步 `handwear` 在内补画处取了 `[131,153,203]`，原图那里是 `[38,48,61]`；
`silhouette_clip` 只压淡边、`swap` 在色差 > 34 时保留模型色，于是蓝块留下。修法：
`fix_colour_specks`（只处理 ≤400px、色差 > 55、原图 alpha > 0.85 的小块，取原图 RGB 写进覆盖层，两遍）。

### 3. 视线（第 5 条）：指标在两次运行里完全一样，**我无法复现用户看到的现象**

8 个 `ParamEyeBallX/Y` 姿态下，虹膜越出原图眼眶开口的像素：run3 与 run4 都是 **0/0**，
眼周 3px 环带暗线均值 l 99.0（run4 还是 99.0）、r 138.0（还是 138.0）。也就是说，第 5 步新增的
"虹膜按画好的开口裁切"（`iris_clipped_to_opening`，p2 姿态裁掉 3.5%/4.1%）在这套"导出姿态 PSD"
的检具里没有产生可测差异。用户描述的"视线向下时虹膜跑到眼眶外"可能来自网页播放器里的其它环节
（蒙皮/物理/眼白网格），需要人工在 `run4/step8/web/` 里点 `ParamEyeBallY=-1` 核对。
我没有为了让指标好看而换检具。

### 4. 脖子（第 6 条）：根因是 neck 层比脸窄，下巴两侧交给随头移动的层

run3 的 `neck` 层 32579px、bbox (424,478)–(598,700)，只在脸中部（脸 bbox 334–680）；
下巴两侧 x 334–424 / 598–680 的皮肤由 `ears`/`face` 提供，它们随头整体移动，转头时缝就出现在
这两个角上。本轮 `rebuild_neck` 重写为：按行找原图的"皮肤连续段"（alpha>0.9、chroma 0.05–0.22、
暖色、亮度>90），在下巴以上取脸的宽度（隐藏 130px），下巴以下取原图整行的皮肤范围（延伸 169px、
进到领口里），并把原图不透明处直接取原图颜色。结果：

| 量 | run3 | run4 |
|---|---|---|
| neck 层不透明 px | 32579 | **60784** |
| bbox 宽度 / 下巴以下延伸 | 174px / 112px | **295px / 169px** |
| 脖子皮肤走廊内透明 px（rest / ±AngleX / ±AngleZ） | 0 / 2,0 / 26,0 | **0 / 0,0 / 0,0** |
| 拍平色差（第 6 步 vs 原图） | 3.34 | **3.002** |

"皮肤走廊"= 原图中下巴以下、左右脸宽范围内的皮肤像素再膨胀 1px；只有那里的透明才算"隔着脖子看到
背景"。若把膨胀加到 9px（会连带把发丝边缘算进来），run3 是 209/70px、run4 是 0/0。

### 5. 耳坠（第 7 条）：不是"两份耳坠图层"，是 `back hair` 里烤进了耳坠图案

在耳坠自身轮廓内（`earwear` alpha 腐蚀 1px，624px）逐层看：

| 层 | run3 亮像素 / 平均色 / 与原耳坠图案 NCC | run4 |
|---|---|---|
| `back hair` | **333 / [162.8,160.4,162.5] / +0.457** | **0 / [39.9,38.7,39.7] / −0.137** |
| `ears` | 11 / [143.6,129.1,126.4] / +0.856 | 11 / [158.4,133.0,124.4] / +0.808 |

`back hair` 在原图那里是深色头发（~60–80），所以"亮像素"就是第二份耳坠。修法：把 `earwear` 轮廓
（膨胀 3px = 1294px）在**其它所有层**里无条件 inpaint（不看颜色，颜色相近的副本会被漏掉），
`back hair` 1294px、`ears` 233px 被重画。导出模型里只有 1 个 `ArtMeshEarwear`。
两点如实记录：
- `earwear` 层自身有 **2 个连通块**（面积 383/157 或 545/233），这是素材本身"耳钉 + 坠子"两块，
  不是副本；so 判据写成"其它层在耳坠轮廓内 = 0"，而不是"连通块 = 1"。
- p5/p6 姿态下 `earwear` 的形心位移（−14.5px / −9.4px）与 `ears`（−31.7px / +30.7px）不同，
  这是 psd2live 的头部变形按位置分配的结果，不是副本。要做到完全同步，只能把耳饰并进 `ears` 层
  （失去独立图层与独立不透明度），本轮没做。

### 6. 头部变形强度（第 8 条）：只有 MCP 能设，CLI 没有这个参数

`headStrength` 只在 `settings_update`（编辑器/MCP）里可改，`psd2live run --input x.psd` 没有对应开关，
所以本轮把它做成 `config.json → step8_export.head_strength.variants`（默认 1.0、软 0.5），每个变体导出
`hsp`/`hsn` 两个姿态后恢复默认值。两组设置之间的差异（同一姿态、同一模型，只改这个参数）：

| 姿态 | 平均色差 | 最大色差 | >10 的像素 |
|---|---|---|---|
| hsp (`ParamAngleX=30,ParamAngleY=30`) | 2.557 | 203.42 | 89679 |
| hsn (`ParamAngleX=-30,ParamAngleY=30`) | 2.837 | 208.34 | 95260 |

即该参数确实作用于脸与五官的变形，不是无效果的空设置；run3 没有这个字段（compare 里为空）。
