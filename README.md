# mira-scene · 深夜下播的忧奈

一个移动端优先的实时互动场景：凌晨两点，新人主播**忧奈**（22 岁，个人势）刚要下播，直播间只剩你一个观众。你可以发弹幕或按住麦克风说话，她会用语音回应，表情、动作、镜头和直播间画面跟着对话变化；聊到她为什么不想播了，剧情会推进到她的「第一次开播截图」，最后在结尾关掉推流。

- 仓库：https://github.com/GongJiYang/mira-scene
- 演示录屏：⏳ 录制后补链接
- 演示地址：**http://45.128.220.44:5173/**（Mock 模式，回复为预置剧本和预录语音）。浏览器只允许 HTTPS 或 localhost 使用麦克风，所以这个地址上**只能发文字弹幕**，要体验按住说话请在本地运行。

## 快速开始

```bash
pnpm i && pnpm dev          # 打开 http://localhost:5173
```

- **不需要任何 Key**：没有 `.env` 时默认 Mock 模式，本地剧本加上预录的忧奈语音，可以完整走完 arrive → probe → reveal → ending。
- **真实模式**：复制 `.env.example` 为 `.env`，填好 `DEEPSEEK_API_KEY`、`FISH_API_KEY`（生图可选 `IMAGE_API_KEY`），设置 `PROVIDER_MODE=real` 后重启。也可以不改 `.env`，直接在页面的「设置」面板里填自己的 Key，切到真实模式。这些 Key 只保存在你的浏览器里，服务端只在本次会话的内存中使用（D49）。
- 环境：Node 22、pnpm、Chrome / Safari 最新版。麦克风需要 `localhost` 或 HTTPS。
- 冷启动实测（2026-10-28）：从 GitHub 全新克隆，不放 `.env`，依次执行 `pnpm i` → `pnpm smoke`（Mock 端到端冒烟，通过）→ `pnpm dev`，页面返回 200，共 19 秒。本机已有 pnpm 缓存，新机器上还要加上下载依赖的时间，通常 1–3 分钟。

## 1. 系统结构和主要模块

```
浏览器（React 19 + Vite）                       Node 服务端（ws）
┌──────────────────────────────┐   WebSocket   ┌──────────────────────────────────────┐
│ 直播间 UI（live/）             │  统一信封      │ session：会话、轮次、取消                   │
│ 单一 Store + Reducer           │ + turnId      │   ├─ 导演层 director（纯函数）            │
│   A 对话状态机（四态）           │ ◀──────────▶ │   ├─ 剧情 story（服务端权威）              │
│   B 表演状态机（表情/动作）       │               │   └─ 换背景 scene（旁路任务）              │
│   C 剧情媒体状态机（截图/视频）    │               │ 端口/适配器 ports + adapters             │
│ 时间线调度器（可整体取消）         │               │   LLM：DeepSeek ｜ Command Code ｜ Mock  │
│ Live2D 渲染（纯函数出每帧参数）    │               │   STT/TTS：Fish ｜ Mock（预录语音）       │
└──────────────────────────────┘               │   生图：OpenAI 兼容接口 ｜ 预置图           │
                                               └──────────────────────────────────────┘
```

| 目录 | 职责 |
|---|---|
| `packages/protocol` | 前后端共享契约：消息信封、`Beat`、各类封闭词表（zod 校验） |
| `apps/server/src/session.ts` | 一个 WebSocket 一个会话：轮次编号、取消旧轮次、历史、快照与断线恢复 |
| `apps/server/src/director/` | 导演层：把 LLM 的「台词 + 情绪 + 建议」补全为合法的 Beat（动作冷却、镜头、特效、媒体、剧情推进校验） |
| `apps/server/src/story.ts` | 剧情节点 arrive → probe → reveal → ending，只由服务端推进 |
| `apps/server/src/adapters/` | DeepSeek、Fish、生图、Mock，外加故障注入装饰器 `faults.ts` |
| `apps/server/src/scene/` | 弹幕换背景：LLM 扩写场景 → 构图锁 → 参考图生图 → 超时与兜底 |
| `apps/client/src/core/` | 连接、录音、音频播放、时间线调度、打断执行器 |
| `apps/client/src/state/` | Reducer 与三台状态机 |
| `apps/client/src/render/live2d/` | Cubism SDK 渲染；`yunaParams.ts` 按状态计算每帧参数，`postPhysics.ts` 在物理计算之后覆盖主动姿势 |
| `characters/yuna/` | 角色包：人设提示词、剧情节点视觉表、指令、语音包清单 |

## 2. 语音交互与打断流程

**链路**：按住说话 → 整段录音上传 → Fish STT → DeepSeek 流式输出 NDJSON（一行一句）→ 导演层补全为 Beat → 每句交给 Fish TTS → 客户端按**音频时钟**逐句播放语音，并同步字幕、表情和动作。我们没有选端到端实时语音模型：那类模型输出的是音频流，情绪、动作、镜头这些画面指令很难和每一句逐句对齐，也很难做 Mock（D1）。

**打断**：角色说话时，**按住麦克风**（桌面按空格）或者**点一下画面**都能打断。打断执行器在同一帧里同步完成这几步：

1. 停止所有音频，嘴闭上；
2. 清空字幕、尚未播出的动作和媒体事件（时间线上的事件都是可取消调度）；
3. 切到倾听状态；
4. 发送 `interrupt`，服务端中止旧轮次的 LLM 和 TTS 请求。

**迟到响应**：轮次编号 `turnId` 由客户端分配，并且递增。每条下行消息都带着 turnId，旧轮次的消息一律丢弃，不会覆盖当前状态。这条规则用属性测试做了验证：随机打乱消息顺序，确认结果不受影响（D3、D12）。

**为什么用按住说话 + 点击打断，而不用自动语音检测（VAD）**：手机外放时，麦克风会收进角色自己的声音，误触发打断。要让自动检测可靠，必须先做回声消除。按住说话的打断时机是确定的，演示和测试都能 100% 复现。点击打断补上了「我只想让她停下，不想说话」这种情况。代价是对话没有自然对话那么流畅（D2）。

**例外**：剧情截图只绑定剧情事件，不跟随轮次作废。打断不会让已经开始生成的图片白白丢掉（D27）。

## 3. 角色和场景指令设计

每一句回复是一个 **Beat**：

```ts
{ seq, say, emotion, accent, hands, action, camera, fx, media, story }
```

**两层决定，保证画面始终合法**（D29）：

- **LLM 只输出**：台词 `say`、情绪 `emotion`（封闭词表）、可选的建议动作 `suggest`、可选的剧情推进 `advance`、可选的语境表情 `accent`（爱心眼、脸红、哭、黑眼圈等 10 种，D47）。
- **导演层（纯函数）决定其余字段**：动作冷却与优先级、情绪和表情冲突时不采纳、剧情推进校验、按剧情节点查表得出镜头 / 特效 / 媒体。LLM 输出再乱，也不会出现角色没有的动作或素材。导演层用属性测试做了模糊测试。

**剧情节点视觉表**（在角色包里配置）：

| 节点 | 触发 | 画面 |
|---|---|---|
| arrive | 开场 | 全身、直播间常亮、待机小动作 |
| probe | 聊起直播和她本人 | 话题引导弹幕切换 |
| reveal | 问到她为什么不想播了 / 安慰她 | 镜头推近、直播间压暗、开始哭、后台生成「第一次开播截图」 |
| ending | reveal 之后再聊两轮 | 拉回全身、爱心漂浮、透明视频「关推流」叠在 Live2D 上 |

题目的最低要求和对应实现：

- **3 种可辨认情绪**：平静、防备、难过、温暖，再叠加语境表情。
- **2 种非说话动作或视觉状态**：喝饮料、看手机、抱熊、流泪、直播间压暗。
- **1 次环境变化**：推镜、压暗；另外弹幕说「换个背景」会触发生图换场景。
- **对话触发的明显视觉事件**：reveal 时弹出按刚才对话内容生成的开播截图。

所有视觉事件都挂在 Beat 上，时间以该句音频为准，不按计时器播放。

## 4. 模型、媒体方案与第三方服务

| 用途 | 服务 / 素材 | 说明 |
|---|---|---|
| 对话 | DeepSeek V4 Flash（OpenAI 兼容接口） | 关闭思考模式、单次流式调用，首句约 0.8 秒（D31） |
| 语音识别 | Fish Audio `transcribe-1-pro` | 整段上传 |
| 语音合成 | Fish Audio TTS（忧奈专属音色） | 按句合成；Mock 模式使用预先合成的语音 |
| 生图 | OpenAI 兼容图片接口（`IMAGE_MODEL` 可配置） | 开播截图、换背景；失败时退回预置图 |
| 角色 | 忧奈 Live2D 皮套（小fa朵实验室，正版商用授权） | 用 Live2D Cubism SDK for Web 渲染 |
| 结尾视频 | 代码确定性渲染的透明 WebM（VP9）和 HEVC `.mov` | 不是 AI 生成的 |
| 界面 | 自行设计（设计稿 `docs/design/s6u/`） | |

多模态能力做了三种：Live2D 角色动画、由状态驱动的透明视频片段、根据对话生成的场景图片。

## 5. 关键技术选择与取舍

| 选择 | 没有选 | 理由 / 代价 |
|---|---|---|
| STT + LLM + TTS 组合（D1） | 端到端实时语音 | 每句都能带画面指令、方便 Mock；代价是多一跳延迟 |
| 按住说话 + 点击打断（D2） | 自动 VAD | 时机确定、可复现；代价是不够自然 |
| 客户端分配 turnId（D3、D12） | 服务端分配 | 打断那一刻客户端就知道新轮次，不用等往返 |
| 导演层（D29） | LLM 直接输出全部视觉字段 | 画面始终合法；代价是表演灵活度下降 |
| 剧情状态在服务端（D6） | 交给 LLM 记忆 | LLM 只能提议推进，由服务端校验；冻结后又加了保底推进，防止真实模式卡在某个节点 |
| 端口 / 适配器 + Mock（D9） | 直接调 SDK | 无 Key 可体验，测试不发网络请求，Provider 可替换 |
| 正版 Live2D 皮套（D43） | 自研的 AI 自动化 Live2D 流水线 | 流水线迭代了 6 轮，指标逐项修平了，但整体观感达不到主播水准，放到演进计划里 |
| 浏览器自带 Key（D49） | 在界面里改服务端 `.env` | 公开演示时评审可以用自己的 Key，会话之间互不影响 |

完整的决策记录（D1–D49，每条都写了语境、选项和代价）见 `docs/architecture/decisions.md`。

## 6. 已知问题

- **真实模式下结局「关推流」透明视频不播放**：真实生图适配器把结局视频也当成图片去生成，接口返回 400。Mock 模式正常。修法已经定位（视频类媒体改走预置素材），计划和结尾动画一起重做。
- **换背景靠关键词识别**：已经排除「去睡吧」这类日常说法，但新的口语句式仍可能误判或漏判。彻底的方案是弹幕 @ 指令（见第 8 节）。
- **剧情推进依赖保底规则**：真实模式下 LLM 很少主动推进剧情。目前由服务端保底：规则允许推进后，连续两轮 LLM 都没推进，就由服务端强制推进。所以剧情节奏偏「被推着走」。
- **iOS Safari 真机的音频行为没有验证**（自动播放策略、按住说话的录音权限）。
- 没有自动语音检测和回声消除，见第 2 节。
- 动作表里部分表情（爱心眼、黑眼圈）在全身取景下很小，预览时会临时把镜头推近来弥补。

## 8. 如果继续开发两周

1. **自然语音**：先做回声消除，再提供 VAD 免按键模式，并区分真正的打断和「嗯」「对」这类附和。
2. **剧情**：在剧情节点上加分支，加入弹幕 @ 指令（`@换地方` `@动作`），让观众能明确地触发视觉事件。
3. **生成内容**：缓存和复用生成结果，检测明显失败的生成图并重新生成，在关键节点生成短视频。
4. **角色表演**：手臂和尾巴的物理覆盖、运行时换配色、手机端人物占满屏。
5. **Live2D 自动化 AI 制作流水线**（`tools/live2d-pipeline`）：把人工精修沉淀成可以自动判定的指标，用 psd2live 的 MCP 接口让 Agent 按指标自动微调。
6. **语音成本与延迟**：本地部署 Fish Drama3（30B），去掉 TTS 的网络往返。
